                                          Host Your CV on AWS
1. What you do
You have a CV template. In this assessment you put it on the Internet twice. Once it is served by a web server on an EC2 instance, and once by a Lambda function. Both have a public address that anybody can open.
The files of the CV are kept in one S3 bucket, and that bucket is private. The only things allowed to read it are an IAM role for the instance and another IAM role for the function, and you write the policies for both. A visitor who tries to open the file in the bucket directly must be refused.
You work alone, in your own AWS account, on your own CV. To mark it, we open both addresses from outside, try to read your bucket directly, run your evidence script, and read your policies and your README.
A sensible order is: the bucket, the two roles, the EC2 path, the Lambda path, the evidence script, the README.

4. IAM
You write two roles. Keep the JSON of each trust policy and each permission policy in the iam folder of your repository.
The EC2 role is trusted by the EC2 service. Its permissions are exactly these two things and nothing more: s3:GetObject on the objects under site/ in your bucket, and s3:ListBucket on your bucket, only when the prefix is site/. The second one is what lets a sync command work.
The Lambda role is trusted by the Lambda service. It has the AWS managed policy for basic logging, and one inline policy with s3:GetObject on the objects under site/ in your bucket. It has no ListBucket.
In both roles, no action may be a wildcard and no resource may be a wildcard. The managed logging policy is the only exception.
There are no access keys anywhere. Not in the user data, not in the function code or its environment, not in the repository, and not on the instance.
From a shell on the instance (EC2 Instance Connect is fine), try to delete or overwrite one of the objects with the AWS CLI. It must fail with an access denied message. Paste that output into your README.
5. Path A: EC2
One instance running Amazon Linux 2023, of a type that is free-tier eligible (t2.micro or t3.micro). It has the normal public IPv4 address that comes with it. Do not use an Elastic IP.
The EC2 role is attached to it, and the metadata service is set to require IMDSv2.
The security group allows TCP 80 from anywhere. It allows TCP 22 only from one address of your own (a /32), or has no rule for 22 at all. It has no other inbound rules.
The user data is kept in ec2/user-data.sh. It installs and starts a web server and then runs your sync script once.
ec2/sync-cv.sh copies the site/ prefix of the bucket into the web root. After that it replaces the placeholder with EC2 followed by the instance ID, which it reads from the metadata service, and it adds one line to /var/log/cv-sync.log with the time and whether the sync worked.
The sync script runs again on a schedule, at least every 5 minutes. Amazon Linux 2023 has no cron by default, so either use a systemd timer or install cronie. If you change a file in S3, the site changes within 5 minutes without anyone logging in to the instance.
The site serves /, /style.css and /cv.pdf, each with the right content type. Plain HTTP is enough. HTTPS is not required.
6. Path B: Lambda
Runtime Python or Node.js, the latest one offered. Memory between 128 and 256 MB, and a timeout of 10 seconds.
The bucket name and the prefix come from two environment variables called BUCKET and PREFIX. They do not appear in the code.
It uses the Lambda role from section 4.
It has a public function URL with the authentication type NONE. The console adds the permission that lets anyone call it. Find that permission in the Permissions tab of the function and be ready to explain it.
What it returns depends on the path in the request.
Path
Response
/ and /index.html
The page with the placeholder replaced by Lambda and the function name. Content type text/html, and Cache-Control with max-age of 60
/style.css
The stylesheet, with content type text/css
/cv.pdf
The PDF, with content type application/pdf. It is binary, so it has to be sent base64 encoded with the matching flag set
Anything else
Status 404 and a short HTML page. Not an error, and not 200
Every request writes one line of JSON to the log with the fields fn, path, status and ms. The retention of the function's log group is set to 7 days.
The code is kept in the lambda folder of the repository.
7. The evidence script
Write a Bash script called collect-evidence.sh in the top folder of the repository. It takes three arguments: the bucket name, the EC2 address and the Lambda address. If it does not get exactly three, it prints a usage line and exits with 1. It writes everything to evidence.txt, and it prints DONE when it finishes.
